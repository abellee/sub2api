# 生产前后端独立部署

基线：生产 v0.2.23-tokenfree.dev.5，提交 7ef4a3ab84518d4a2671861bc1cbfbf99bc0b492。

后端镜像只编译 Go，不嵌入前端。前端镜像独立构建 Vue 并由 Nginx 托管；API 地址、认证、数据库、媒体及审计连接保持不变。上游原有 Dockerfile 和发布方式保留。

## 构建

主站公开仓库的 Build split images 工作流支持分别发布 frontend/backend，私有仓库仍可使用同一流程。镜像使用 sha-完整提交号固定版本。audit SDK 通过私有构建包恢复固定 gitlink 对应的源码并核验；cost-guard SDK 沿用生产已跟踪源码。禁止使用本地其他未发布改动。

## 网页兼容

- 同域名 /api/v1；所有已有模型、媒体、MCP、OAuth 路由继续转发。
- HTML 不缓存；哈希资源长缓存；/usr/share/nginx/previous 只读挂载历史资源，旧标签页仍可加载旧模块。
- HTML 通过内部 Nginx 子请求读取后端实时 CSP 和公开中转页开关；后端只增加无副作用的公开页面检查，不改变业务接口。
- 公开设置由现有前端 API 回退加载。静态首页标题沿用生产 TokenFree 文案；后台品牌配置仍由前端加载，HTML 不再注入 window.__APP_CONFIG__。
- 现有 data/public 若有覆盖文件，发布前逐项配置只读挂载。此次生产核查为空。
- API 不缓存、不缓冲流式输出、不由代理重试生成请求。

## 生产滚动切换

沿用原滚动控制器的备份、临时候选、连接排空、结算等待、审计队列确认和恢复流程。第一轮仅改变镜像和网页承载，不做数据库迁移，不扩展成长期多后端实例。

1. 完成统一测试、构建与发布后，预拉取并核验两个镜像摘要。
2. 候选后端使用原临时端口 18082；候选前端只监听 127.0.0.1:18083。
3. 平滑调整现有 OpenResty 入口到候选前端；本机媒体回调继续沿用原临时转发规则。
4. 等原后端外部连接归零并完成原有结算等待，才更新正式后端。
5. 正式前端只监听 127.0.0.1:18081，指向正式后端 8080；入口平滑转回正式前端。
6. 再等待候选前端/后端连接归零、结算等待和审计队列清空，才移除候选容器。

不设强制排空截止时间。任何无法确认的连接保留，禁止为完成发布强行终止用户请求。异常时根据切换阶段保留可用实例与配置备份，不盲目重放已受理请求。

## 验收

统一运行原有后端/前端 CI、安全检查、拆分配置与真实 Nginx 代理测试。覆盖路由、SSE、WebSocket、Range、请求正文、客户端 IP、CSP、关闭的公开中转页及历史资源。

线上验证只使用用户 2 的身份、Key 和任务；没有样本的项目明确记未验证。此次不主动发起付费生成。连续健康探测只是入口可达证据，用户请求保护以连接排空、结算等待及审计队列检查为准。

后续独立发布前端时也需保留历史资源并平滑替换代理；独立发布后端时继续使用上述滚动流程。数据库、Redis、现有辅助服务和外部域名不迁移。
