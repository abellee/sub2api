# 费用预检

系统设置 → 功能设置 → 费用预检，默认关闭。关闭时仅估算和输出日志，不因估算拒绝请求，也不为这次估算登记余额预留；开启后才执行预检拦截。保存后在当前进程立即生效；其他实例在 30 秒内同步。普通余额、配额检查和实际计费照常执行。

预估费用 =（本次输入量 × 输入价格 + 最大输出量 × 输出价格）× 分组计费倍率。沿用主站渠道价格优先的定价结果。文本请求按实际输入内容估算，复用主站本地 token 计数和协议转换：包含系统提示、对话历史、工具定义、调用参数和工具结果；JSON 转义先还原。图片编码、加密思考和请求元数据不按文本 token 计费，也不再用整个请求体大小触发长输入加价。Gemini 沿用主站文本粗估并计入工具内容；媒体本身的 token 仍是估算盲区。

输出优先使用请求携带的上限；未携带时使用价格目录中的 max_output_tokens（其次 max_tokens），都没有则用现有 default_max_tokens 配置（默认 8192）。只用于估算，不修改发给上游的请求。

长输入加价与计费规则一致：遵循分组的长输入开关；使用自定义价格区间时不重复叠加模型加价，无区间时按模型门槛调整输入、缓存读取、缓存创建和输出价格。仅日志和实际拦截使用同一套估算规则，便于校准。

可设置拒绝时的 HTTP 错误码（400–599，默认 403）和错误信息（最多 2000 字，留空使用默认提示）。单次预估超过余额、并发在途预留不足和显式配置的无法定价拒绝统一使用该响应；其他计费限制不受影响。沿用各端点的错误格式，类型为 cost_precheck_failed；流式响应如果已发送心跳，HTTP 状态无法修改，错误码通过流内错误消息的 code 返回；已升级的 WebSocket 通过错误事件携带状态码和信息后关闭连接。保存后当前进程立即生效，其他实例在 30 秒内同步。

已有计费任务顺手记录同一 API Key、分组、请求模型上一笔的普通输入、缓存读取和缓存创建比例；本次按该比例折算输入费用。没有历史、历史超过 10 分钟、读写竞争或价格异常时忽略缓存。历史只在本进程内保存，有容量上限；重启即清空。

开启时复用原有余额读取结果，预估费用超过余额则拒绝；其余在途并发保护继续由主站负责。关闭时只读取余额缓存用于记录预计判定，读取最多等待 100 毫秒，失败则记录余额未知，不回查数据库；不执行预留、续期、释放或无法定价拒绝。仅日志模式不登记在途预留，不能模拟并发冻结后的可用余额，日志中的在途金额为 null。

没有后台用量扫库、上游计数请求或等待历史写入。两种模式都在需要估算时于本地解析输入一次，多个候选计费模型复用结果，实际使用历史也继续更新。无法解析输入时跳过新增估算，不能保证完全杜绝透支。旧版的分组平均缓存率、估算安全系数、冻结登记和解冻结果日志已停止接入。

每次检查输出一条 INFO 日志 `cost_guard.precheck`，写入现有应用日志，不另存数据库。包含请求 ID、客户端请求 ID、用户/API Key/分组 ID、请求时间与检查时间、请求模型和采用的计费模型、预估总输入/普通输入/缓存读取/缓存创建/输出 token、输出上限来源、缓存依据、分组倍率、输入输出预估费用和总费用（美元）、实际预留金额、当时余额及其他请求在途预留、判定结果和原因。`mode=log_only` 表示只记录，`decision=allow`、`reason=log_only` 表示实际放行；`estimated_decision` 和 `estimated_reason` 记录根据本次估算和余额预计会否拒绝，包括无法估算时的 skip。`mode=enforce` 表示已开启拦截，`decision` 为 `allow`（放行）、`reject`（拒绝）或 `skip`（无法估算、无需计费或缓存故障等，跳过检查放行）。未读取的余额和在途金额为 null。`cache_source=previous_usage_ratio` 表示使用上一笔的缓存比例估算，不是本次上游实际命中；`no_history` 表示按无缓存处理。记录采用本次判定实际使用的估算快照，不重算，不记录请求正文或凭据。订阅模式和简易模式不参与费用预检或预检日志。
