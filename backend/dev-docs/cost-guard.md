# 费用预检

系统设置 → 功能设置 → 费用预检，默认关闭，保存后在当前进程立即生效；其他实例在 30 秒内同步。

预估费用 =（本次输入量 × 输入价格 + 最大输出量 × 输出价格）× 分组计费倍率。沿用主站渠道价格优先的定价结果。输入沿用请求体字节数 / 4 的粗估，不额外解析请求。

输出优先使用请求携带的上限；未携带时使用价格目录中的 max_output_tokens（其次 max_tokens），都没有则用现有 default_max_tokens 配置（默认 8192）。只用于估算，不修改发给上游的请求。

长输入加价与计费规则一致：遵循分组的长输入开关；使用自定义价格区间时不重复叠加模型加价，无区间时按模型门槛调整输入、缓存读取、缓存创建和输出价格。关闭预检时保留原有估算行为。

可设置拒绝时的 HTTP 错误码（400–599，默认 403）和错误信息（最多 2000 字，留空使用默认提示）。单次预估超过余额、并发在途预留不足和显式配置的无法定价拒绝统一使用该响应；其他计费限制不受影响。沿用各端点的错误格式，类型为 cost_precheck_failed；流式响应如果已发送心跳，HTTP 状态无法修改，错误码通过流内错误消息的 code 返回；已升级的 WebSocket 通过错误事件携带状态码和信息后关闭连接。保存后当前进程立即生效，其他实例在 30 秒内同步。

已有计费任务顺手记录同一 API Key、分组、请求模型上一笔的普通输入、缓存读取和缓存创建比例；本次按该比例折算输入费用。没有历史、历史超过 10 分钟、读写竞争或价格异常时忽略缓存。历史只在本进程内保存，有容量上限；重启即清空。

开启时复用原有余额读取结果，预估费用超过余额则拒绝；其余在途并发保护继续由主站负责。关闭后完全跳过新增估算规则和余额比较，主站原有检查仍然保留。

没有后台用量扫库、额外请求解析、逐请求对账日志或等待历史写入。无法估算时跳过新增检查，不能保证完全杜绝透支。旧版的分组平均缓存率、估算安全系数、冻结登记和解冻结果日志已停止接入。
