# 管理员日志采集与耗时排查

入口：管理员 → 日志采集 → 耗时排查。

填写用户 ID、分组 ID、账号 ID，确认开启。三个条件同时匹配：分组使用 API Key 请求进入时的分组；账号匹配请求实际选中过的账号。一次请求重试其他账号时，也保留该请求的其他尝试，以便解释完整等待时间。

每次开启生成 UUID。按采集标识查询历史，选中采集后可按请求编号或 `client:…` 查询。采集在请求结束后异步入库；开始后请发起新请求。停止保留历史，丢弃尚未保存的记录，包括在途请求。后续重新开启使用新 UUID。

## 记录范围

- 鉴权完成、请求体读取、用户/账号并发等待、账号选择、上游请求准备。
- 通用 HTTP 上游：等待连接、DNS、TCP、TLS、上传完成、首响应字节、响应头、首响应体字节、响应体读完。连接复用时不会产生 DNS/TCP/TLS 阶段。自定义传输不支持的回调不填。
- OpenAI Responses SSE：首个流事件与首次内容分别记录。其他协议仍记录 HTTP 阶段及原有业务耗时指标。
- OpenAI WS：连接获取、上传完成、首个事件、首次内容。客户端 WS 按连接结束入库，多轮计入尝试；采集开启前已建立的连接需要重新建立才会被采集。没有实际观测到的数据大小显示为空。
- 首次向下游写入和刷新缓冲区、请求结束。心跳也可能成为首次写入，这不等同于用户看到首字。

页面时间轴单位毫秒，保留小数。阶段耗时显示对应起止时间差；未知或起止倒序显示“—”，不是零。部分阶段相互包含，不能直接相加。时间从请求到达应用开始计算，不含客户端到反向代理的传输、反向代理缓冲、上游内部处理分段和客户端渲染。

不保存 URL、请求头、对话内容、图片、Key 或错误原文；仅保存关联 ID、时间、传输方式、状态码、字节数。

## 开销和停止语义

- 默认关闭。热路径读取内存配置，不查询数据库。
- 仅为匹配用户/分组分配计时器，实际选择目标账号才保存。
- 最多 10 个活动采集；每次最多 10,000 条，达到上限自动停止。
- 每请求最多 32 次上游尝试、256 个阶段；超限明确标记。流事件只保存每尝试的首次时间。
- 每实例异步队列最多 256 条；满时丢弃，不阻塞业务。写入失败不无限重试。进程退出时放弃未保存队列。
- 配置每 2 秒同步；超过 10 秒未成功同步则暂停采集。当前实例开启后立即刷新配置，其他实例约 2 秒收敛。
- 停止与写日志锁定同一数据库行：停止返回成功后，任何实例都不能再为该采集插入记录，即使仍持有旧配置。
- 页面队列/失败计数是当前实例自启动以来的累计值，不是全站聚合数。记录数量保存在数据库中。

## 接口与发布

接口均沿用管理员认证与操作审计，受限管理员密钥默认没有这些新接口的权限。

- `GET /api/v1/admin/ops/latency-collections?collection_id=&before=`：每页 50 个采集。
- `POST /api/v1/admin/ops/latency-collections`：`user_id`、`group_id`、`account_id` 为必填正整数，实体必须存在。
- `POST /api/v1/admin/ops/latency-collections/:id/stop`：重复停止不改变历史停止时间。
- `GET /api/v1/admin/ops/latency-collections/:id/records?request_id=&before=`：每页 50 条，按返回的 `next_before` 翻页。

首次发布需要后端、前端和迁移 `262_latency_collections.sql` 一起发布；该功能上线后，开始/停止采集不需要重启服务。没有主动删除历史的定时任务。
