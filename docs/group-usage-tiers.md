# 分组阶梯倍率

- 后台「分组」→「阶梯倍率」选择每日实扣金额或每日 Token 数（正整数），设置对应门槛、连续达标天数、连续未达标天数和专属倍率。
- 按北京时间自然日统计，同一用户在来源分组的所有 Key 合计。Token 数为输入 + 输出 + 缓存创建 + 缓存读取，与页面 Token 总数口径一致；启用前的用量不补算。
- 达标当日立即获得该阶倍率；下一阶从次日重新计天。未达标会中断升级连续天数。
- 保级按当前已获得阶梯的金额或 Token 门槛计算。任意一天达标即清零未达标天数；连续未达标达到配置天数，在次日零点取消全部阶梯倍率，从第一阶重新开始。
- 最高阶锁定升级进度，仍需保级。未结束的当天不会提前记作未达标。
- 关联分组共享来源分组的阶梯结果和倍率；关联分组的用量不反向计入来源分组。关联不会递归传递。
- 阶梯倍率与原有倍率取更低值；独立图片、视频倍率及高峰规则保持原有计算顺序。
- 不参与用户仍可查看规则说明，但不显示进度，也不获得此规则的倍率。列表仅后台可见。
- 修改达标模式、统计模型、阶梯条件或启停规则会从保存时重新累计；原样保存、调整关联分组及不参与用户不重置进度。关闭规则后停止该规则。
- 用户页面每分钟更新进度；计费时独立读取当前结果。多实例间规则启停最多有 5 秒缓存。
- 每日金额和 Token 汇总独立保存，不随原始用量日志清理。部署需要执行数据库迁移 `275_group_usage_tiers.sql` 和 `276_group_usage_tier_tokens.sql`。

- 两种模式的模型范围均可选本分组全部模型或指定模型；多个指定模型合计达标，以用量日志的客户端请求模型名精确匹配，历史缺少该字段时使用 model。
- 不参与用户通过用户名/邮箱搜索选择，以标签显示，可逐个移除；仅管理员可见。
- 迁移 276 将已有金额规则标记为金额模式，保留启用状态、门槛和已获得的进度，并复制历史金额汇总；不会自动换算或停用。切换到 Token 模式须设置 Token 门槛，并从保存时重新累计。
