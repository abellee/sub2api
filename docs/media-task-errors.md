# 媒体任务错误与 SLA

主站任务查询先判断任务是否失败，只有成功任务的文件清理后才返回过期。失败任务使用已有错误关键词规则匹配，客户端只收到规则配置的提示或固定失败提示，不收到上游正文。媒体站的 `error_context` 只接受带签名和任务归属校验的内部请求，正文最多保留 8KB。

SLA 使用 `ops_error_log_metrics.is_sla_sample` 统一判定。普通请求仍按原规则统计；带任务 ID 的生图失败响应和任务状态查询，对同一用户、同一任务只计算最早的一次有效失败。重复查询、换查询地址、跨小时查询都不增加失败数。没有任务 ID 的普通生成失败保持逐请求统计。

所有查询错误继续保存在 `ops_error_logs`，错误总量和请求量也保留原值；只有 SLA 及上游错误率使用去重样本。认证失败、任务不存在等查询错误不代表生成失败。已经有成功结算记录的任务，过期和删除后的查询不计入生成失败。

历史版本将失败任务也报为 410，无法仅凭该响应区分失败和过期。对于没有成功结算记录的旧 410，保守地保留一次失败；已有成功记录则排除。去重依据仍在保留期内的错误日志，历史日志已经清理的部分无法恢复。

迁移 253 添加统一判定视图，254 添加并发索引，255 修复现存小时及每日汇总中受影响的统计。不会删除错误日志、修改账单或重新生成图片。实时统计、错误趋势、状态码分布、后台指标采集和后续汇总都使用同一判定。

数据库验证使用独立的本地数据库：设置 `OPS_SLA_TEST_DSN` 后运行 `go test ./internal/repository -run TestMediaTaskSLAPostgres -count=1`。测试创建独立 schema 并在结束后清理，覆盖百次重复查询、跨小时、不同查询地址、首次同步失败、旧 410、成功后过期及历史汇总修复。
