# 账号报错后的换号

系统设置 → 网关设置 →「账号报错自动重试换号」，以及本次使用的分组开关都开启时生效。默认关闭；关闭时保持原有处理。

同一分组、同一模型有多个可用账号时：

1. 上游错误直接换下一个账号，不先在同一个账号上重复尝试。包括 404、上游账号欠费、认证失败、模型不可用、限流、服务错误和连接错误；不再只按少数状态码判断。
2. 本站用户余额不足、无权限、参数不合法、上下文超长和内容拒绝等用户问题不换号。上游返回“用户额度不足”指供应商账号余额，属于第 1 类，不能当成本站用户欠费。
3. 本次请求遍历可用账号一次，没有固定六次上限。8 个可用账号最多尝试 8 个；15 个最多尝试 15 个。手动关闭、不支持本模型或不可调度的账号不计入。
4. 客户端断开、请求总时限到达或候选账号用完就停止。这些失败不触发账号自动停用或冷却。

只有一个可用账号时保持原有处理，不增加这项功能的换号和重试。系统或分组开关关闭时也不扩大错误重试范围。

流式响应按每次账号尝试判断是否已输出，前一个账号写过响应不能阻挡后一个账号尚未输出时的换号。已输出情况下继续保留各协议现有的安全限制；失败尝试已经报告的用量仍单独保留，不能把这部分用量当成最终成功。

错误详情新增“换号最终结果”：成功、失败、客户端断开或请求超时。成功时显示成功账号 ID；原有错误账号字段仍指报错账号，便于排查供应商。历史记录没有最终结果字段时不猜测成功，HTTP 200 也不单独作为成功依据。

规则用于主站的账号转发循环。Gemini 显式缓存、已经绑定账号的视频任务继续使用所属账号；独立 mediad 异步任务不经过这一循环，不能因轮询报错重新创建生成任务。后台刷新凭据和原有用量限制继续独立生效。

换号可能延长等待；上游已经执行但返回失败时，重新请求仍可能产生额外供应商费用。
