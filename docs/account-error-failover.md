# 账号报错后的重试与换号

系统设置 → 网关设置 →「账号报错自动重试换号」，默认关闭。关闭时所有分组均不启用这项功能，保持原有处理。

分组的新建、编辑页面也有「账号报错自动重试换号」，默认关闭。只有系统开关和本次实际使用的分组开关都开启时才生效；没有分组的请求不启用。复制分组时保留该设置。

仅统计开启且可调度的账号。手动关闭或暂停调度的账号不参与重试、换号，也不会被自动开启。

开启且同一分组、同一模型有多个可用账号时：

1. 当前账号首次失败后，再重试 2 次，共最多尝试 3 次。
2. 仍失败就换另一个账号；本次请求不再选已经尝试完的账号。
3. 所有候选账号都失败后返回错误，不重新开始下一圈。
4. 这些失败不触发账号停用或冷却；后续请求仍可选择这些账号。

只有一个可用账号时，保持原有处理，不增加上述重试与换号规则。

开启这项功能时，Gemini 的 Messages、原生和 Chat Completions 入口统一由外层控制每号最多三次，不叠加 Gemini 原有的同号重试次数。日志中的 `failover` 表示该次错误可换号；实际切号以账号 ID 变化及 `gateway.failover_switch_account` 记录为准。

重试范围沿用各接口原有的可换号错误。请求错误、明确要求停止的错误，以及已经返回内容或部分结果的请求，不自动重发。客户端断开后停止重试。Gemini 显式缓存和已绑定的视频任务继续使用所属账号，不跨账号重试。

开启这项功能后，OpenAI Responses 首段文字中的纯空格、换行先缓存，不算已输出；后续正常输出时会保留这些空白并按原顺序返回。只有空白就发生上游错误，仍可重试和换号。工具参数、工具输入、拒绝及加密推理内容保持原有输出保护。

OpenAI Responses 普通转发流的数据间隔超时，在尚未输出实际内容时也会进入重试和换号，并记录上游 504；一旦已经输出内容，则在原连接中返回超时错误，不重新发送请求。总请求超时或客户端取消仍立即停止。关闭功能或只有一个可用账号时保持原有处理。

Anthropic、Chat Completions、Responses 的上游读错误、提前结束、缺少结束事件和流数据间隔超时，在尚未向客户端写出响应时也进入上述重试流程。非流式入口即使上游内部使用流式传输，只要还没有返回客户端，也可重试。已写出的协议事件、文本和工具内容均不能撤回，不重新发送。上游自身超时与客户端取消分别判断：客户端请求仍有效时可重试上游超时；客户端取消或请求总时限到达后停止。

后台主动刷新凭据和原有用量限制继续独立生效。重试可能增加等待时间；图片、视频等请求若上游在报错前已经执行，仍存在重复执行或上游计费的可能。
