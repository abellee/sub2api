# 流式错误统一处理

后端在现有协议解析处识别错误，再匹配错误透传规则。普通文字、图片和工具调用不再经过 OpenResty 的 SSE 拼接、JSON 解析和重复扫描。

- 已命中规则：按规则选择文案；仅明确开启错误正文透传时保留经过脱敏的上游消息。
- 未命中规则：返回“当前服务拥挤，请重试。”，原始错误继续保存在后台。
- 尚未输出：保留现有换号顺序，结束重试后才选择对客错误；支持修改 HTTP 状态码的出口按规则返回。
- 已经输出：保持 HTTP 200，使用客户端原有协议发送错误事件；不拼接两次模型回复，不修改已收到的正常内容。
- Responses 的 error、response.failed、只有 error 后断流的结束消息，Chat 原生/兼容、Claude 原生/兼容、Gemini 原生/兼容和媒体错误出口均接入规则。

OpenResty 使用 `deploy/openresty-error-body.inc`。成功和 SSE 响应不检查正文；OpenResty 自身产生或后端尚未明确处理的 HTTP 错误仍使用固定提示。后端选定的错误通过内部响应头标记，入口移除该头后保留选定文案。现有 HTTP 错误头清理及搬瓦工媒体限制保留。

上线顺序：先滚动部署后端并确认所有旧请求结束，再备份并替换两个入口规则文件，关闭应用入口的 `proxy_intercept_errors`，检查配置后平滑重载。回退时先恢复入口规则，再回退后端。

发布验证仅使用用户 2；协议和分块错误通过隔离模拟验证，不调用收费模型。
