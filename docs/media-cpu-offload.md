# 媒体处理移到媒体站

主站负责鉴权、选择账号、预留和结算费用、保存用户下载记录；媒体站负责参考图转码、生成、等待、文件保存、图片正文编码和流式消息组装。

无限画布代码和静态文件保持原样。普通图片同步提交后返回 `data[].url`；明确要求 `b64_json` 时仍返回 Base64。Gemini 保留 `candidates[].content.parts` 和文字内容，把图片正文替换成 `fileData.fileUri`。视频提交同时返回 `id` 和 `request_id`，完成后同时提供 `video.url`、`video_url`、`url`，兼容原生调用和现有视频脚本。文件预览、下载、播放和分段读取直连媒体站；原任务查询仍通过主站验证身份并转发少量状态信息。

任务链接只能读取单个任务的状态和已结算文件链接，不返回账号凭证、提示词、参考图或图片正文。未结算时只返回 processing；文件过期返回 410。任务链接依赖中转签名密钥，轮换该密钥会使已有任务链接失效；已经下载到画布本地的文件不受影响。下载链接仍遵循现有媒体保留设置。

普通 OpenAI、Gemini、Grok 图片接口保留原格式。主站只向媒体站发起一次等待请求，直接转发响应字节，不再每 0.3 秒发 HTTP 查询，也不解析和重新编码图片。参考图上传仍经过主站并执行大小检查和签名，文件转 Base64 在媒体站执行。因此主站仍有网络转发、加密、鉴权和计费开销，不能保证 CPU 恒为零。

部署应先升级媒体站，再升级主站，不更新画布静态文件。媒体站公开入口继续使用现有 `/downloads/`，需要允许 GET/HEAD、保留响应中的跨域头；无需开放新端口。主站升级依赖新版媒体站的一次等待接口，不可单独上线。回退按相反顺序进行，并避免中断已受理任务。

验收包括原客户端同步和 Base64 返回格式、Gemini 文件链接、视频原接口及分段下载、主站不再转换参考图或查询循环、媒体站流式心跳和逐张结果、未结算访问拒绝、任务链接隔离和重启恢复、失败/过期/取消。使用模拟上游完成这些检查，不发起付费生成。
